Findings and fixes

SRP Single Responsibility 2.5 → 4.5

What was wrong

admin.routes.ts was a 3658-line module holding 81 routes across 15 unrelated concerns — catalog, job queue, email, analytics, geo ingestion, moderation, billing, scraping — importing 17 infrastructure modules and running 64 raw SQL statements inline. agent-geo.routes.ts repeated the pattern at 1238 lines. index.ts was simultaneously the process entrypoint, an HTTP handler, an HTML templating engine and the cron schedule; its start() ran 570 lines. submitGuess was 509 lines mixing authorization, anti-replay, anti-oracle, timer validation, scoring, persistence, achievements and webhooks.

What changed

  • Admin router split into 16 focused modules; parent is 62 lines of guard + mounts. Route set verified byte-identical: same 81 method+path pairs.
  • Agent geo router split into 5 modules + shared helpers; parent 57 lines. Same 15 routes.
  • Entrypoint decomposed: bootstrap/scheduled-jobs.ts, health.routes.ts, share.routes.ts. 984 → 424 lines.
  • submitGuess's scoring pipeline, anti-cheat rules and end-of-session ceremony each extracted into named, tested units.

Ordering was load-bearing in the entrypoint — the share shells must sit after express.static or the static index.html shadows them, and before the SPA fallback. Verified structurally rather than by eye: expanding each extracted router back in place yields the same 39 mounts in the same order.

Residual

submitGuess remains ~430 lines. Every decision inside it is now an extracted, tested, pure unit; what is left is sequencing and persistence calls. Linear orchestration of that length is defensible, but it is the obvious next target.

OCP Open/Closed 3.0 → 4.8

What was wrong

Achievement criteria were dispatched by two parallel switch statements (21 and 10 cases) in a 943-line service. Adding a criterion meant remembering to edit both; forgetting the second silently shipped an achievement whose progress bar never moved. Geo ingestion had the same shape — a six-branch if (source === ...) chain whose last source was an unlabelled fall-through.

What changed

Both became declarative registries where each variant owns all of its behaviour, typed as Record<ClosedUnion, Handler>. Omitting a handler is now a compile error, not a runtime warning:

src/domain/services/achievement.service.ts(723,9): error TS2741:
  Property 'brand_new_criterion' is missing in type '{ ... }'
  but required in type 'Record<"perfect_score" | ... , CriterionHandler>'

Verified by temporarily adding a criterion type and confirming the build fails.

The refactor surfaced a latent bug. geogamers_runs_completed and geogamers_perfect_run are seeded into the achievements table but awarded by key from the GeoGamers route, so they hit the old default: branch and logged "Unknown achievement criteria type" after every classic game. They are now registered explicitly as handled-elsewhere.

Guard

A test parses the migrations and asserts every seeded criteria.type is registered, so the table and the code cannot drift apart again.

LSP Liskov Substitution 4.5 → 4.7

This was already the strongest dimension and needed no repair. The backend uses interfaces plus factory functions throughout; there is no implementation inheritance to violate. The only extends in the codebase widens interfaces, which is substitutable by construction.

It improved slightly as a side-effect of the ISP work: a service that depends on a four-method role interface can be handed any conforming object, so substitutability is now exercised in practice rather than merely available in principle.

ISP Interface Segregation 2.5 → 4.5

What was wrong

Five ports were single wide interfaces that every consumer depended on wholesale, however little they used:

PortMethodsReality
SessionRepository25admin.service calls 1, geo-game calls 1
AchievementRepository23three unrelated roles in one interface
ChallengeRepository15leaderboard.service calls 1 — and could write challenges
UserRepository15four consumers with near-disjoint 2–5 method slices
GameRepository13game.service calls 3, all reads — yet could delete a game
DomainLogger7trace and fatal called by zero services

What changed

Each split into role interfaces, with the original name retained as the union the concrete repository implements — so the composition root passes the same objects and no runtime wiring changed. Several services can now no longer reach methods they have no business calling: the leaderboard cannot write a challenge, achievements cannot write to the user table, the game loop cannot touch referral columns or delete a catalog entry.

A cast was hiding a defect. The fat interfaces forced as unknown as in test doubles. Removing one revealed that the leaderboard test's challenge fixture was { id: number } where a full ChallengeRecord was required — the cast had silenced it. Another was {} as unknown as UserRepository: an empty object standing in for fifteen methods.

Residual

achievement.service genuinely uses 18 of its 23 repository methods, so its test double is still cast. That is a signal the service itself is doing too much, not that the port is wrong — it belongs to the SRP backlog.

DIP Dependency Inversion 3.0 → 4.9

What was wrong

CLAUDE.md states the rule as "presentation → domain → infrastructure; domain has no outward deps". The file asserting it was breaking it: the bottom 330 lines of domain/services/index.ts were a composition root importing the Pino logger, four BullMQ queues, the Socket.io emitter and 23 concrete repositories. Importing a domain type opened a Redis connection.

Meanwhile Express handlers ran 107 raw Knex statements, and billing.service.ts imported Stripe.Subscription straight from the vendor SDK.

What changed

  • Composition root moved to src/composition/; the domain barrel is now pure. All 30 importers redirected.
  • All 107 raw SQL statements moved behind repositories, including three multi-table transactions.
  • Vendor type replaced by a domain-owned ExternalSubscription naming the four fields actually read. A real Stripe subscription still satisfies it structurally, so no call site changed.

Two copies of one rule had already drifted apart. The SSE stream hand-rolled its own ranking query — a line-for-line copy of leaderboardRepository.rankForScore — on a surface whose entire point is that a streamer's overlay and their public profile agree. Both now call the same method. The same "resolve user ids to public slugs" query appeared three times in one file.

Guard

Six tests in domain/architecture.test.ts make the layering rule executable instead of aspirational. They assert the domain imports nothing from infrastructure/ or presentation/, that no domain service pulls in bullmq / ioredis / knex / kysely / socket.io / stripe / express / pino, and that no presentation file imports the Knex instance.

testConnection remains allowed in the readiness probe — checking the database is reachable is exactly that endpoint's job. The rule bans the query builder, not the module.
